The basics everyone needs.

Whatever path you pick, these carry you. If a session ever felt like it went too fast, the gap is usually one of these.

Git and GitHub

Save versions of your work, collaborate without overwriting each other, and show your code to employers.

  • GitHub Skills
  • Pro Git book

The command line

Every path uses it. Moving around folders, running programs and reading errors calmly.

  • The Missing Semester (MIT)
  • OverTheWire Bandit

How the web works

What happens when you type a URL. DNS, HTTP, servers and browsers, explained once properly.

  • MDN: How the web works

Problem solving

Breaking a problem down, basic data structures, and thinking before typing.

  • CS50x (Harvard)
  • freeCodeCamp

Using AI well

Use assistants to learn faster, not to skip learning. Always read and test what they write.

  • Gemini API docs
  • Google Prompting Essentials

Asking good questions

Show what you tried, the exact error and a small example. You will get answers twice as fast.

  • How to ask (Stack Overflow)

Pick a path. Here's the road.

Each path has an order that works, free places to learn it, and a first project worth putting on your CV.

Game development

For people who want to make things others play. Coders, artists, writers and sound people all fit.

First projectA one-screen arcade game with a high score.

Learn it in this order

  1. 1Pick one engine: Godot (free, light on old laptops) or Unity
  2. 2Make a tiny 2D game: move, jump, collide, score
  3. 3Learn game feel: juice, sound, feedback
  4. 4Ship a build to itch.io and get strangers to play it

Free places to learn

  • Godot: your first 2D game
  • Unity Learn
  • Flame engine (Flutter)
  • Blender tutorials

Web development

For people who want to build things anyone with a browser can use.

First projectA site for a real person: a friend's business, a lecturer, the club.

Learn it in this order

  1. 1HTML and CSS: structure and layout
  2. 2JavaScript: make pages do things
  3. 3A framework (React) and a backend (Firebase)
  4. 4Deploy it and share the link

Free places to learn

  • MDN: Learn web development
  • The Odin Project
  • web.dev Learn
  • Firebase docs

Mobile

For people who want their work in someone's pocket.

First projectA timetable or expense tracker you actually use.

Learn it in this order

  1. 1Kotlin or Dart basics
  2. 2Jetpack Compose (Android) or Flutter (both platforms)
  3. 3Store data and call an API
  4. 4Publish a release build

Free places to learn

  • Android Basics with Compose
  • Flutter: get started
  • Kotlin docs

AI and machine learning

For people curious about how machines learn, and how to build useful things with models.

First projectA study helper that summarises your own lecture notes.

Learn it in this order

  1. 1Python and a bit of NumPy and pandas
  2. 2Core ML ideas: training, overfitting, evaluation
  3. 3Build with a model API (Gemini)
  4. 4Train or fine-tune your own small model

Free places to learn

  • Google ML Crash Course
  • Kaggle Learn
  • Practical Deep Learning (fast.ai)
  • Gemini API docs

Cloud and DevOps

For people who like making systems reliable, fast and cheap to run.

First projectContainerise a club project and deploy it on every push.

Learn it in this order

  1. 1Linux and networking basics
  2. 2Containers with Docker
  3. 3Deploy to a cloud (Cloud Run, Firebase Hosting)
  4. 4Automate it with CI/CD

Free places to learn

  • Google Cloud training
  • Docker: get started
  • DevOps roadmap

UI/UX design

For people who notice when something is confusing and want to fix it.

First projectRedesign one painful student portal screen, then test it with five classmates.

Learn it in this order

  1. 1Design basics: type, spacing, colour, hierarchy
  2. 2Figma: components and prototypes
  3. 3Talk to users and test with them
  4. 4Hand off designs developers can build

Free places to learn

  • Material Design 3
  • Figma Learn
  • Laws of UX
  • Google UX Design Certificate

Data

For people who like finding the story inside numbers.

First projectAnalyse a public Zimbabwean dataset and publish what you found.

Learn it in this order

  1. 1Spreadsheets properly
  2. 2SQL
  3. 3Python with pandas
  4. 4Dashboards that answer one question each

Free places to learn

  • SQLBolt
  • Kaggle Learn: Python and pandas
  • Google Data Analytics Certificate

Cybersecurity

For people who like puzzles and figuring out how things break.

First projectAudit a club project for the OWASP Top 10 and fix what you find.

Learn it in this order

  1. 1Linux and networking
  2. 2Web vulnerabilities: the OWASP Top 10
  3. 3Capture-the-flag practice
  4. 4Secure your own projects first

Free places to learn

  • TryHackMe
  • OverTheWire
  • OWASP Top 10
  • Google Cybersecurity Certificate

Habits of people who ship.

  • Commit small, commit often

    One change per commit with a message that says why. Future you will thank you.

  • Write the README first

    What it is, how to run it, a screenshot. Half of judges and recruiters read nothing else.

  • Never commit secrets

    API keys and passwords go in environment variables, not code. Leaked keys get abused within minutes.

  • Test the part that would hurt

    You don't need 100% coverage. Test the logic that loses data or money if it breaks.

  • Build for slow phones

    Most of your users are on mobile data. Smaller images, less JavaScript, works offline where it can.

  • Make it accessible

    Real labels, enough contrast, works with a keyboard. It's also what makes it usable for everyone else.

  • Review code kindly

    Ask questions instead of giving orders. Everyone on the team is learning.

  • Read the error message

    All of it, slowly, top to bottom. Then search it. Most bugs are explained in the first line.
